Attributed starts from a reproducible import of the [pinned upstream tree](/baseline), not from a fork of its history. Each later slice changes one owner and keeps its own evidence. Run the [qualification plan](/qualification) checks that a slice affects before merging it.

## Reproduce the import

[`tools/upstream-import/import_upstream.py`](https://github.com/amichne/attributed/blob/main/tools/upstream-import/import_upstream.py) reads blobs from commit `d4260838249720bcea3a746cce809e5a1955248a`. It drops the excluded paths, applies the naming map to paths and content, and runs `gofmt`. It refuses an existing destination, a symlink or submodule entry, non-UTF-8 content, a rename collision, and any `byline` or `comarch` text that survives outside the files kept verbatim.

Verify import commit `11c6d61` from the repository root with Git, `uv`, and `gofmt` on `PATH`:

```sh
work=$(mktemp -d)
git clone --no-checkout https://github.com/comarch/git-byline.git "$work/upstream"
uv run --locked --script tools/upstream-import/import_upstream.py "$work/upstream" "$work/import"
mkdir "$work/tree" && git archive 11c6d61 | tar -x -C "$work/tree"
diff -r -x .mintlify -x docs -x README.md -x LICENSE.upstream -x upstream-import \
  "$work/import" "$work/tree" && echo MATCH
```

The excluded names are the files that existed before the import and the codemod itself. Two independent runs produced identical trees, and this check printed `MATCH`.

## Naming map

Every upstream name changes to an Attributed name. The rules apply in this order to paths and to content:

| Upstream form | Attributed form | Examples |
| --- | --- | --- |
| `comarch.git-byline` | `amichne.attributed` | Agent Trace metadata key |
| `comarch/git-byline` | `amichne/attributed` | Module path, release and raw URLs, action references |
| `git-byline` | `git-attributed` | Binary, `cmd/git-attributed`, hook commands, backup suffixes |
| `BYLINE` | `ATTRIBUTED` | `GIT_ATTRIBUTED_VERSION`, `ATTRIBUTED_BIN` |
| `Byline` | `Attributed` | Go identifiers such as `readAttributed` |
| `byline` | `attributed` | `refs/notes/attributed`, `refs/worktree/attributed/checkpoints`, `.git/attributed/` state |

The binary stays a Git subcommand, so `git attributed blame <file>` works when `git-attributed` is on `PATH`. Plugin author fields name the Attributed maintainer. `marketplace/git-attributed/LICENSE` keeps the upstream notice byte for byte.

The rename changes wire identities, so an Attributed install does not read or write upstream records:

- Notes live under `refs/notes/attributed`, `refs/notes/attributed-stash`, and `refs/notes/attributed-remote`. Read a note with `git notes --ref=attributed show <commit>`.
- Worktree state lives under `attributed/` in the Git directory, with snapshots reachable from `refs/worktree/attributed/checkpoints`.
- Hook ownership markers name `git-attributed`. Uninstall does not remove hooks that upstream installed.
- Git AI export hashes the producer name into the synthetic human ID and the checkpoint trace IDs. The import regenerates `internal/interop/testdata/gitai-export.golden` from `sha256("git-attributed")` and `sha256("git-attributed:checkpoint:7")`.

Reading existing `refs/notes/byline` records is a separate compatibility decision. It needs a fixture from an upstream install and a test that keeps the two namespaces distinct.

## License in the binary

Attributed is MIT licensed. `LICENSE` holds the Attributed notice and `LICENSE.upstream` holds the Comarch notice. The root package embeds both files, and `git-attributed license` prints them. The release-style build test checks that the compiled binary prints both copyright lines. Release archives should also include both files when release automation exists.

### Project harness integrations

Upstream generated its hook payloads with the PromptScript CLI from sources that the import left out. Attributed follows the Slopsentral projection pattern instead. `marketplace/` and `commands/` are generated consumers. Change their source and regenerate them; do not edit them by hand.

| Owner | Contents |
| --- | --- |
| `integrations/Integrations.pkl` | Tool matchers and timeouts for Codex, Copilot, Cursor, Gemini CLI, Grok, and VS Code. It also holds the plugin manifest metadata and the closed list of assets. |
| `integrations/assets/` | Setup commands, READMEs, the skill, the OpenCode plugin, and the Gemini command, at their output paths. `@@sha256:<path>@@` embeds the digest of another projected file. |
| `tools/projection/Schema.pkl` | Each provider's file shape, its `portable-<id>` preset, and how its hook command reaches the project root. |
| `tools/projection/Project.pkl` | The file plan: rendered hook files, both plugin manifests, the plugin license from `LICENSE.upstream`, and the assets. |
| `tools/projection/project.py` | Freezing, evaluation, sealing, the lock, publication, and the drift check. |

The driver requires Pkl 0.33.0 and evaluates with `--root-dir` set to a frozen copy of the inputs. It allows only `pkl:` and `file:` modules and only `file:` and `prop:` resources, with a 60-second limit. A first pass renders seals as 64 zeros. The driver digests each referenced file and evaluates again with those digests. It then verifies that only the placeholders changed. It writes `marketplace/projection-lock.json` with the source digest and every file digest. Publication renames a complete sibling staging tree into place and refuses an existing destination. Every failure prints `PROJECTION_REJECTED stage=<stage> code=<code>`. The codes cover missing or non-regular sources, a missing or unpinned Pkl, evaluation failures, unsafe or duplicate paths, undeclared assets, missing or chained seals, changed inputs, existing outputs, and drift.

To change an integration, edit its source, then regenerate and check:

```sh
uv run --locked --script tools/projection/project.py publish --out /tmp/attributed-projection
rm -r marketplace commands
cp -R /tmp/attributed-projection/marketplace /tmp/attributed-projection/commands .
uv run --locked --script tools/projection/project.py check
```

The projection reproduced every imported file byte for byte, with one exception. The rename had left the OpenCode setup command's plugin checksum at upstream's digest, so setup would have refused the renamed plugin. The seal now supplies the projected plugin's digest. The projector tests cover rejected plans, sealing, publication, drift on a changed matcher, and a zero timeout. Pkl's `isPositive` admits zero, so the schema requires `this > 0`.

The first payload change after parity removed the upstream PromptScript names:

| Before | After |
| --- | --- |
| `.github/hooks/promptscript.json`, `.github/hooks/promptscript-vscode.json` | `.github/hooks/git-attributed.json`, `.github/hooks/git-attributed-vscode.json` |
| `.grok/hooks/promptscript.json` | `.grok/hooks/git-attributed.json` |
| `.opencode/plugins/promptscript.ts` and `marketplace/harness/opencode/promptscript.ts` | `.opencode/plugins/git-attributed.ts` and `marketplace/harness/opencode/git-attributed.ts` |
| `# promptscript-generated:<tag>` hook markers | `# git-attributed-hook:<tag>` |
| `PROMPTSCRIPT_PROJECT_ROOT` and `$promptscriptProjectRoot` | `ATTRIBUTED_PROJECT_ROOT` and `$attributedProjectRoot` |

The installers and the `update` hook refresh used the same paths until slice 4 removed them. All 32 projected POSIX hook commands ran under `sh` with a stub `git-attributed`. Each one reached the project root and called its `portable-<agent>` checkpoint, or failed with its message when the root was missing. The PowerShell variants were not run.

A projected file proves only what the package contains. Harness discovery and hook delivery still need evidence from a live session. These gaps remain:

- No release exists. The setup commands find `git-attributed` on `PATH` and stop if it is missing. The OpenCode setup command still downloads its plugin from a release tag, so that step fails until a release exists.
- The repository publishes no Claude Code or Factory marketplace listing and no Gemini extension manifest, so the package installs in the harness README do not work yet.
- `git-attributed install-hooks` writes the Claude Code and Factory hooks from Go in `internal/hooks`. The projection does not own those hooks.

### Remove out-of-scope producers

Slice 4 removed these capabilities. Each one went with its packages, callers, and tests:

| Capability | Removed |
| --- | --- |
| HTML dashboards, statistics, and policy checks | The `dashboard`, `stats`, and `check` commands, and the `dashboard` and `report` packages |
| Compliance disclosure | The `disclosure` command and package |
| Forge workflows | The `ci` command and package, workflow provisioning in `install-hooks` and removal in `uninstall`, `action.yml`, and `action/` |
| Self-update and release checks | The `update` command, `version --check`, the `runner` package, the release-tag helpers in `internal/version`, `install.sh`, and `install.ps1` |
| Token accounting | `blame --tokens` and the transcript usage collector. Capture no longer records usage. |

These capabilities remain. `transcript` still resolves the model from session files. `parseRevisionRange` moved to `verify.go`, its only remaining caller. `shortCommit` moved to `product.go` for the same reason. Notes and pending checkpoints that an older producer wrote with token usage still parse, and annotation still folds their usage into note sessions. The setup commands no longer download the binary. They find `git-attributed` on `PATH` and stop with build instructions if it is missing.

A test checks that each removed command now fails as unknown. The smoke suite has 16 stages. Its report stage now runs `verify` and both exports, and checks that each removed command exits 2. It dropped the dashboard stage.
